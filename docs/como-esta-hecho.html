Cómo está hecho

Cada lunes un Action despierta, trae datos frescos de la API pública de GitHub y regenera todo el sitio. Sin servidor, sin base de datos: 17 archivos HTML autónomos con los datos dentro.

1. API de GitHub. scripts/fetch_top.py trae los 500 con más estrellas y fetch_trending.py los creados el último mes. Usa GITHUB_TOKEN cuando existe y pausas en anónimo para respetar el límite.
↓
2. Español + taxonomía. describe.py añade descripción en español, categoría (IA, Frontend…) y tipo (herramienta, lista, educativo).
↓
3. Foto semanal. snapshot.py guarda un resumen en data/history/: así nacen la racha 🔥, las gráficas y la API versionada.
↓
4. Excel. export_excel.py genera los dos XLSX con hipervínculos y filtros nativos.
↓
5. Sitio. build_site.py incrusta ambas bases en cada tema, build_paginas.py genera Analytics y Noticias, gen_landing.py la portada; verify.py valida el JavaScript con node, los datos y el contraste; los tests E2E lo abren en Chromium de verdad.

Sesgos y límites honestos

Estrellas ≠ calidad: miden popularidad y antigüedad tanto como mérito. El corte del Top 500 está hoy en ~20.000 estrellas, así que proyectos nuevos y buenos tardan en entrar (para eso está Tendencias). Las categorías y descripciones en español se generan por palabras clave (src/ranking/taxonomia.py): a veces se equivocan. Las licencias vienen de la API y a veces faltan (sin dato no significa sin licencia).

La API

Los mismos JSON del sitio, versionados por fecha en data/history/. Campos en SCHEMA.md del repositorio. Ejemplo:

fetch("data/history/2026-09-14-top.json").then(r => r.json())

Refresco: lunes 06:00 UTC vía .github/workflows/refresh.yml.

Privacidad

En local no hay rastreo de ningún tipo: todo funciona con doble clic y sin cookies. En producción el sitio usa Umami (analytics open source, sin cookies ni banner) solo para contar visitas y saber qué temas se usan.
